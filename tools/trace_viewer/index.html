Формат RunTrace: events, initial_state, model_input / output,
code_check, node_update и final_state.

Файл обрабатывается локально. Подключение к интернету не требуется.

Как читать trace.json

Маршрут — последовательность посещений нод, включая повторные попытки. «Весь маршрут» показывает все события. Цвета: LLMКодОшибкаОбновление

Вход ноды — состояние, восстановленное из initial_state и предыдущих node_update. Для messages, agent_code_history и agent_error_history используется добавление списков, остальные поля заменяются. Это правила GraphState данного проекта; для другого графа реконструкцию нужно сверить с его reducers. Фактический запрос LLM смотрите в model_input.messages.

model_input → model_output / model_error связываются по run_id. messages — пакеты сообщений; type задаёт роль (system, human, ai), content содержит текст или блоки. В response.generations находятся варианты ответа: text и message часто повторяют один ответ. Структурированный код может быть JSON-строкой в content или аргументами tool_calls.

node_update.update — только изменения, возвращённые нодой. generation содержит prefix (описание подхода), imports и code. input_classifier_response — уточнённая постановка. Истории агентов хранят сообщения генерации и диагностики.

code_check — реальная проверка: stage, returncode, stdout, stderr или error при исключении/таймауте. Ненулевой returncode означает ошибку; непустой stderr сам по себе ошибкой не считается. error="yes" в состоянии — флаг повторной генерации, error="no" — проверка пройдена.

final_state — накопленный итог: messages, generation, input_classifier_response, две истории агентов, error и sim_logs. Верхнеуровневый status="success" означает завершение запуска; внутри могли быть исправленные ошибки. Пустой sim_logs означает отсутствие вывода, а не отсутствие запуска.

Ограничения лога. В текущем формате нет событий входа/выхода нод и явных переходов рёбер. Посещения сгруппированы по завершающему node_update, принадлежность code_check выведена из порядка событий. Это подходит последовательному графу проекта; при параллельных ветках нужны node/run_id для каждого события. Финальное состояние показано непосредственно из файла. Длительность ноды и незафиксированные действия по этому логу точно не определяются.

Метаданные провайдера, идентификаторы и статистика токенов по умолчанию скрыты. Любое поле можно включить в панели слева. Тексты показываются как текст, код из файла не запускается.
