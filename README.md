## Где версии системы

В ветках проекта есть папка system. В ней есть две версии. Первая версия создана для моделирования двухзвенного маятника. Вторая модель была создана для моделирования подвески гоночного автомобиля.

## Подготовка окружения 

Создайте виртуальное окружение и активируйте его:
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```
Для Linux/macOS: `source .venv/bin/activate`.

Установите зависимости:
```bash
python -m pip install -r requirements.txt
```

## Как запускать
### Первая система
Нужно вызвать файл main.py и указать yml файл с описаниями объектов. Yml файл должен содержать описание запроса и название запроса, пример можно найти в ветке первой системы.
`python main.py request.yaml`

### Вторая система
Вторую мультиагентную систему можно аналогично запустить
`python main.py request/requst_suspension.yaml`

Если не требуется отчёт о проделанной работе, то можно отключить работу последнего агента 
`python main.py request/requst_suspension.yaml --skip-insight`

Можно еще указать папку для сохранения всех артефактов работы системы. По умолчанию это папка results
`python main.py request_suspension.yaml --skip-insight --output-dir results`

Артефакты которые можно получить после запуска:
specification.json — параметры, единицы и допущения;
physical_subsystems.md — физические подсистемы и обмен величинами;
subsystems.py — функции подсистем;
model.py — самостоятельная запускаемая модель;
simulation_report.md — объяснение модели, если последний агент включён;
прежние <имя запроса>.py, <имя запроса>.md и trace.json.

Для второй мультиагентной системы предусмотрены инструменты:

1. Просмотр трассировки осуществляется на специализированной html странице tools/trace_viewer/index.html
2. Создание анимации для модели tools/animate_simulation.py

#### Launcher
Суть лаунчера в том, что после генерации модели можно сразу же провалидировать её. Берётся траектория z_u и сравнивается
с помощью расстояния L2. При расстоянии L2 < 1 можно считать, что модель адекватная. Ошибка *абсолютная*
`python launcher.py --prompt-file suspension_request.txt`

## Описание мультиагентной системы

### Вторая модель

Пайплайн выполняется последовательно:

1. input_classifier получает исходный запрос и формирует SimulationSpecification. Для каждого параметра указаны имя, символ, смысл, значение, единица СИ, исходное значение с единицей, категория, значимость и источник (user или inferred). Число параметров зависит от задачи. Допущения, переменные состояния, метод расчёта и требуемые результаты описываются отдельно. Спецификация сохраняется в JSON.
2. subsystem_design получает исходный запрос и спецификацию. Агент выделяет физические подсистемы, описывает уравнения, состояния, сигнатуры функций и связи: кто кому передаёт величину, её имя, единицу измерения, знак и систему координат. Документ также задаёт порядок вычислений и решение связанных ограничений. physical_subsystems.md записывается до генерации кода.
3. code_generation по этому документу реализует функции всех подсистем. Результат сохраняется в subsystems.py; запуск симуляции в этом модуле не предусмотрен.
4. model_assembly получает функции, описание взаимодействий, спецификацию и исходный запрос. Он пишет код связей, численного решения, CLI и вывода результатов. Код функций сохраняется в итоговом model.py вместе с кодом сборки: итоговая программа не требует отдельного импорта subsystems.py.
5. code_execution_import_check проверяет импорты и исполнение в отдельном Python-процессе, во временном каталоге, с тайм-аутом 300 секунд. При ошибке диагностирующий агент получает полный код и логи; диагноз передаётся обоим агентам реализации. Повторяются этапы 3–5, максимум три попытки по умолчанию (max_iterations). После исчерпания попыток запуск завершается с ошибкой, без итогового объяснения.
6. create_insight, если включён, кратко описывает полученную физическую модель, её параметры, ограничения и запуск Python-кода. Отчёт сохраняется в simulation_report.md.
