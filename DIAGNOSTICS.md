# Диагностика агента

Проверка выполнена для точки входа `pipeline.py` и вызываемого ею модуля `code_nodes.py`. Файлы успешно проходят синтаксическую проверку `python -m py_compile`, но в графе есть несколько ошибок времени выполнения.

> Статус после исправлений: ошибки 1, 2, 3, 9 и 10 устранены. Для ошибки 5 добавлен явный вывод имени отсутствующего пакета. Остальные пункты документа описывают состояние исходной реализации и остаются актуальными.

## Критические ошибки

### 1. Ветка обработки отсутствующего импорта сама падает

**Место:** `code_nodes.py:74-87`.

Сгенерированные `imports` и основной код объединяются и выполняются через `exec`. `ModuleNotFoundError` корректно попадает в `except`, однако строка 81 пытается сложить объект `SystemMessage` со списком:

```python
messages = agent_error_prompt + [prompts_tasks[...]]
```

Это вызывает `TypeError: unsupported operand type(s) for +: 'SystemMessage' and 'list'`. В результате диагностирующая модель не вызывается, флаг `error="yes"` не возвращается и граф не переходит к повторной генерации.

Даже после исправления этой строки остаётся второй сбой: текст задания передаётся как обычная строка, а должен быть сообщением, например `HumanMessage`; затем результат `invoke()` (один `AIMessage`) возвращается в поле `messages`, хотя reducer этого поля ожидает список. При слиянии состояния возникнет ошибка вида `list + AIMessage`.

**Что требуется:** формировать список `[agent_error_prompt, HumanMessage(...)]`, а из узла возвращать `"messages": [error_message]`.

### 2. История генератора объявлена с неверным типом

**Место:** `pipeline.py:28-29`.

Поля `agent_code_history` и `agent_error_history` аннотированы как одиночный `HumanMessage`, но используют `operator.add` и фактически получают списки сообщений. Это противоречие ломает контракт состояния и затрудняет валидацию/сопровождение.

**Что требуется:** использовать `Annotated[list[AnyMessage], operator.add]` (или специализированный reducer сообщений). Поле `agent_error_history` сейчас вообще не используется.

### 3. Финальный узел всегда падает после успешного исполнения

**Место:** `code_nodes.py:123-132`.

`state["generation"]` является экземпляром Pydantic-модели `code`, но строка 125 складывает его со строкой:

```python
print("GENERATION AAA " + state["generation"])
```

Это вызывает `TypeError`. Поэтому даже корректно сгенерированная и выполненная симуляция не может штатно завершить граф.

Кроме того, вызов `agent_insighter` закомментирован, а узел возвращает пустой словарь. Заявленный отчёт/инсайт фактически не создаётся.

### 4. Повторная генерация не ограничена

**Место:** `pipeline.py:45-48`, `code_nodes.py:45-50`.

При любой повторяемой ошибке переход `execution -> regenerate -> generation -> execution` не имеет счётчика попыток и аварийного выхода. В документации `GraphState` упомянуто поле `iterations`, но в самом состоянии его нет. Агент может расходовать запросы до достижения внешнего recursion limit или иной ошибки.

## Существенные дефекты

### 5. Отсутствующий пакет принципиально не может появиться

Текущий цикл умеет только просить модель переписать код. Он не классифицирует `ModuleNotFoundError`, не проверяет допустимый набор зависимостей и не устанавливает пакеты. Если модель продолжит использовать отсутствующий импорт, цикл будет повторяться. Нужна явная политика: разрешённый список библиотек и просьба переписать решение на доступных зависимостях либо отдельный контролируемый механизм установки.

### 6. `exec` выполняет непроверенный код в процессе агента

**Место:** `code_nodes.py:77`.

Код модели получает права текущего Python-процесса: может читать/изменять файлы, обращаться к сети, завершить процесс или зависнуть. Нет тайм-аута, отдельного процесса, ограничения памяти и файловой/сетевой песочницы. Бесконечный цикл в сгенерированном коде повесит весь pipeline.

### 7. Импорт `pipeline.py` сразу запускает весь процесс и меняет файл

**Место:** `pipeline.py:51-66`.

Построение PNG, запись `graph.png`, сетевые вызовы моделей и `agent.invoke()` находятся на уровне модуля. Поэтому простой `import pipeline` имеет тяжёлые побочные эффекты. Также граф компилируется дважды (строки 51 и 59).

**Что требуется:** вынести запуск в `main()` и защитить `if __name__ == "__main__":`.

### 8. Конфигурационные файлы ищутся относительно текущего каталога

**Место:** `code_nodes.py:13-18`; аналогично `graph.png` в `pipeline.py:56`.

Запуск из каталога, отличного от корня проекта, приведёт к `FileNotFoundError` или записи PNG не туда. Пути следует строить от `Path(__file__).resolve().parent`.

### 9. Сообщения дублируются в состоянии

**Место:** `code_nodes.py:53, 91-95` совместно с reducer `pipeline.py:24`.

На успешной проверке узел возвращает весь уже существующий список `messages`. Reducer `operator.add` добавляет его к существующему списку повторно. Следует возвращать только новые сообщения либо не возвращать поле, если оно не изменилось.

### 10. Теряется исходный пользовательский запрос в рабочей истории генератора

После классификации генератор создаёт новую историю только из системного промпта и результата классификатора. При исправлении ошибки он использует историю структурированных ответов генератора и последний диагноз, но системный prompt может отсутствовать в повторном обращении. История хранит ответы модели, а не полный корректный диалог `system -> human -> assistant -> correction`, что делает исправления менее устойчивыми.

## Дополнительные замечания

- Имя `code_execution_import_check` содержит опечатку и вводит в заблуждение: отдельная проверка импортов закомментирована, выполняется весь код.
- `stderr` захватывается, но нигде не сохраняется и не возвращается.
- Вызов `exec(code)` без отдельного словаря делает окружение исполнения неявным; последовательные запуски могут загрязнять глобальное пространство модуля.
- В `GraphState` применён `Field(...)` внутри `TypedDict`; это не задаёт обязательные runtime-значения. Для необязательных ключей следует явно использовать `NotRequired`, а начальное состояние формировать полностью.
- В проекте нет зафиксированного файла зависимостей, поэтому воспроизводимость окружения и перечень гарантированно доступных импортов не определены.

## Приоритет исправлений

1. Исправить типы сообщений в обработчике исключений и reducer состояния.
2. Добавить лимит попыток и отдельную обработку `ModuleNotFoundError`.
3. Исправить/реализовать `create_insight`.
4. Перенести исполнение кода в изолированный процесс с тайм-аутом.
5. Убрать побочные эффекты импорта и сделать пути независимыми от текущего каталога.
