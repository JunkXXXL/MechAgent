# Краткая логика работы агента

Точка входа `pipeline.py` собирает граф LangGraph из четырёх узлов. Промпты и пользовательский запрос загружаются модулем `code_nodes.py` из `agents.yaml`, `tasks.yaml` и `request.yaml`.

Поток выполнения:

1. `input_classifier` получает исходный запрос пользователя и преобразует его в более полное техническое описание физической симуляции: параметры, допущения, уравнения и численный метод.
2. `code_generation` передаёт это описание модели с structured output. Ответом должна быть Pydantic-структура `code` с пояснением (`prefix`), импортами (`imports`) и телом программы (`code`).
3. `code_excecution_import_check` объединяет импорты с телом и исполняет получившийся Python-код через `exec`, перехватывая стандартный вывод и ошибки.
4. Если исполнение выбросило исключение, `decide_to_finish` должен вернуть граф в `code_generation`: диагноз ошибки добавляется в историю, после чего модель генерирует исправленный вариант.
5. Если код выполнился успешно, stdout сохраняется в `sim_logs`, а граф переходит в `create_insight` и затем завершается.

Задуманная схема выглядит так:

```text
START
  -> классификация запроса
  -> генерация кода
  -> исполнение кода
       | ошибка  -> диагностика -> повторная генерация -> исполнение
       | успех   -> отчёт по симуляции -> END
```

В текущей реализации фактический поток прерывается либо в обработчике ошибки исполнения, либо в `create_insight`; сам отчёт по успешной симуляции пока закомментирован.
